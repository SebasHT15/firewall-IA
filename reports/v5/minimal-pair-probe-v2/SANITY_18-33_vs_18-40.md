# Sanity check — `Transfer-Encoding: chunked`: 18/33 vs 18/40

Date: 2026-10-06. Scope: documentary reconciliation only. **No inference was re-run. No raw
result, protocol, manifest, or SHA-256 anchor was modified.** This note inspects the frozen
minimal-pair probe v1 artifacts and explains why two denominators appear for the same effect.

## Question

Different summaries cite the `Transfer-Encoding: chunked` effect as **18/33** and as **18/40**.
Which N belongs to which comparison, where does each denominator come from, is one a subset of the
other, or is there a documentation error?

## Finding (FACT, from the frozen artifacts)

The two numbers describe the **same 18 ALLOW→BLOCK flips** over **two different, both-correct
denominators**. There is no error in the frozen raw results.

Source: `reports/v5/minimal-pair-probe-v1/results.json`, comparison `F-CL:absent->te_chunked`:

| field | value |
|---|---|
| `n_bases` = `n_valid_pairs` | **40** |
| `ALLOW_to_ALLOW` | 15 |
| `A_to_B` (ALLOW→BLOCK) | **18** |
| `B_to_A` (BLOCK→ALLOW) | 0 |
| `BLOCK_to_BLOCK` | 7 |
| `baseline_allow_rate` | 0.825 → **33**/40 reference texts were ALLOW |
| `flip_rate` | 18/40 = **0.45** |
| `conditional_A_to_B` | 18/33 = **0.5454…** ≈ **0.55** |
| `effect_class` | STRONG EFFECT |

The 2×2 transition counts sum to 40 (15 + 18 + 0 + 7). Of the 40 pairs, the reference (`absent`)
side was classified ALLOW in 15 + 18 = **33** of them; the other 7 were already BLOCK at baseline
(all 7 stayed BLOCK).

Therefore:

- **18/40 = 0.45** is the **unconditional flip rate** — dominant-direction flips over *all* pairs in
  the stratum. This is the `flip_rate` column.
- **18/33 = 0.55** is the **conditional ALLOW→BLOCK rate** — flips among only the 33 pairs whose
  baseline decision was ALLOW (the pairs that *could* flip to BLOCK). This is the `conditional_A_to_B`
  column.

Neither is a subset error; 33 ⊂ 40 by construction (baseline-ALLOW pairs ⊂ all pairs), and the same
18 flips populate both ratios.

## Where each appears in the frozen docs (both correct, both labeled)

- `minimal-pair-probe-v1/results_table.md` line for `F-CL:absent->te_chunked`:
  `N=40 | A→A=15 | A→B=18 | B→A=0 | B→B=7 | flip rate 0.45 | base ALLOW 0.82`. Correct.
- `minimal-pair-probe-v1/README.md` results table: columns report both `flip rate … 0.45` **and**
  `cond. A→B … 0.55`, with reference-ALLOW count 33. Correct and correctly labeled.
- `minimal-pair-probe-v1/README.md:159`: prose "18/33 **among** [baseline-ALLOW pairs]". Correct
  (it is explicitly the conditional denominator).
- `minimal-pair-probe-v1/README.md:241`: "STRONG, 18/33". Correct (conditional rate).

The repo's frozen artifacts only ever print **18/33** for this effect, always as the conditional
rate, and always alongside the 0.45 flip rate. The bare "18/40" framing occurs only in
cross-session prose summaries that quoted the flip rate's implied count without stating the
denominator.

## Resolution

- **No frozen artifact is in error.** Raw results, protocol, manifest, and all SHA-256 anchors are
  unchanged and correct.
- The apparent discrepancy is purely a cross-session **exposition** matter: 18/40 is the flip rate,
  18/33 is the conditional-on-ALLOW conversion rate, both describing the identical 18 flips.
- **Convention adopted for v2 and the evidence matrix:** quote the effect as **18/40 flip rate
  (0.45); 18/33 conditional ALLOW→BLOCK (0.55)**, always naming the denominator. v2 reports both
  columns (`flip_rate` and `conditional_A_to_B`) exactly as the v1 analyzer already does, so the
  ambiguity cannot recur.
