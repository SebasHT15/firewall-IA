1. WHAT THE FINAL POLICY DID (D17 FINAL — "H2")
==============================================================================
TWO INDEPENDENT LEVERS, controlling two DIFFERENT quantities.

1a. LOGICAL-GROUP CAP = 2,500, POLICY B  — diversity dominance control
    Applied BEFORE rendering. Policy B means CSIC-derived BLOCK groups count
    toward the SAME per-category budget as PayloadsAllTheThings/hardcoded
    groups. Selection is first N by sorted group id (sha256 of the canonical
    payload) over the merged pool, so it is deterministic, order-independent,
    and does not prefer either source.

    CAPPED (4 categories):
      Directory Traversal   10,218 -> 2,500   (-7,718 attack / -0 CSIC)
      SQL Injection          2,953 -> 2,500     (-203 attack / -250 CSIC)
      File Inclusion         2,937 -> 2,500     (-437 attack / -0 CSIC)
      XSS Injection          2,628 -> 2,500     (-110 attack / -18 CSIC)

    PRESERVED AS-IS (15 categories, all below the cap):
      Command Injection 453 · SSTI 368 · Open Redirect 242 · SSRF 201 ·
      XXE 98 · NoSQL 83 · JWT 80 · LDAP 75 · GraphQL 74 · CSRF 31 ·
      XPath 24 · CRLF 21 · HPP 20 · Insecure Deserialization 12 ·
      Request Smuggling 7

1b. RENDERED-ROW CAP = 4,000  — training contribution control
    Applied AFTER rendering and deduplication, BEFORE final balancing.
    Malicious categories only; benign is never row-capped.

    Selection: deterministic, SOURCE-STRATIFIED (quota split between
    PayloadsAllTheThings and CSIC in proportion to their row counts, by
    largest remainder, so neither source is deleted first), and BREADTH-FIRST
    (one row per logical group before any second row).

    ONE category exceeded the cap:
      SQL injection    rows 5,545 -> 4,000  (-1,545)
                       groups 2,500 -> 2,500   *** 100% RETENTION ***
                       CSIC rows 3,699 -> 2,668

    THE KEY METHODOLOGICAL RESULT: the row cap removed 1,545 REDUNDANT
    RENDERINGS while eliminating ZERO represented logical diversity. Every
    other category retains 100% of its groups because none exceeded the cap.

1c. WHY BOTH ARE NEEDED
    A group cap alone cannot control training contribution. A CSIC group is a
    request SHAPE that collapsed many original records, and every record still
    renders. Measured at a 2,500-group cap, SQL Injection still produced 5,545
    rows while Path Traversal produced 2,511. The row cap acts directly on the
    quantity that determines training contribution.

1d. HARD FLOOR, ENFORCED IN CODE
    row_cap must be >= group_cap. Below it the breadth-first round robin
    exhausts its budget on the first pass and group retention pins at exactly
    row_cap/group_cap (measured: 2000/2500 -> 80.0% in four categories). The
    generator now REFUSES to run below the floor rather than silently
    destroying logical diversity.

     Proxy capture (CONTEXT.md section 8) remains the stronger long-term fix.

  7. E0 measures EXACT overlap only. Canonical grouping addresses near
     duplicates by construction, but a minhash/shingle metric would strengthen
     the guarantee. Not implemented.
