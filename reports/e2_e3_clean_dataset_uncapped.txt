2. GENERATOR ARCHITECTURE
==============================================================================
parse_dataset_v4.py is a NEW file. parse_dataset.py is deliberately left
untouched and fully executable: it is the control condition for the E2
before/after comparison, and deleting it would make that comparison
unreproducible.

Nine stages, in the order D16 requires:

  1. source extraction        PayloadsAllTheThings + hardcoded + CSIC
  2. normalization/filtering  quality gate with per-reason accounting
  3. canonical logical sample encoding/case/whitespace-invariant key
  4. group identity           sha256 of the canonical key
  5. train/eval GROUP split   deterministic hash bucket
  6. shared envelope render   ONE generator for both classes
  7. training augmentation    TRAIN_TRANSFORMS only, within the group's split
  8. validation               invariants asserted, build fails otherwise
  9. JSONL + manifest         SHA-256, counts, limitations

The critical inversion vs the historical generator:

  HISTORICAL:  source -> variants -> shuffle -> random row split
  CLEAN:       source -> group    -> split   -> render -> augment

3. E2 — SHARED ENVELOPE AND SHAPE MATCHING
==============================================================================
The historical generator drew ALLOW and BLOCK from different envelope
distributions. Fixing shortcuts one at a time would not have worked: E0 found
seven of them, and patching Host alone would have left Content-Type at 82.62%.

The structural fix has two parts.

3a. ONE SHARED ENVELOPE GENERATOR
  build_envelope() is the only source of Host, User-Agent, Accept*, Connection,
  X-Requested-With and Cookie values, and it is called by both classes. There
  is no benign-only or attack-only host, user-agent or cookie anywhere in the
  file. Envelope values are drawn from an RNG seeded by the sample's GROUP ID,
  so they are deterministic per sample and statistically independent of label.

  The historical benign-only host pool (api.example.com and friends, 0 BLOCK)
  and attack-only host (target.internal.com, 0 ALLOW) are gone: both pools were
  merged into one 32-host list used by everything, including CSIC.

  CSIC records are RE-RENDERED under the shared envelope. Method, path, query
  and body — the semantic content — are preserved exactly. Only the envelope is
  redrawn. This removes the `Host: target.com` + single-Konqueror-UA signature
  that made CSIC origin identifiable.

3b. SHAPE MATCHING
  A "shape" is the structural envelope of a request: valid methods, path pool,
  parameter names, content type, special headers. 15 shapes are defined.

  Every attack category maps to one or more shapes. The benign generator then
  produces benign traffic in the SAME shapes at MATCHED volume. So for every
  XML-body XXE attack there is benign XML/SOAP traffic; for every Bearer-token
  JWT attack there is benign authenticated API traffic; for every GraphQL
  injection there is a benign GraphQL query.

  This is what collapsed Content-Type (82.62% -> 50.71%), header-name set
  (76.84% -> 49.58%), header count (75.88% -> 49.88%) and body presence
  (74.12% -> 50.00%) simultaneously, rather than one at a time.

3c. RESIDUAL METHOD CONFOUND — FOUND AND FIXED DURING THIS PHASE
  The first generation run still showed HTTP method at 56.37% (+6.37). It was
  investigated rather than accepted, per the E0 instruction.

  Cause: two compounding asymmetries.
    (i)  A generator bug. Benign volume was matched to attack GROUP count
         (18,413), but augmentation emits ~2 rendered rows per group, so the
         shared-envelope population was ~2:1 BLOCK-heavy. The leftover ALLOW
         mass was CSIC, which is GET/POST-only 2010 traffic. Result: PUT,
         PATCH, DELETE and HEAD skewed ~70% BLOCK.
    (ii) CSIC's own method mix differs between its Normal and Anomalous
         records, and that difference is inherent to the source capture.

  Fixes applied:
    (i)  Benign demand now matches RENDERED BLOCK ROWS per shape, not groups.
    (ii) Final class balancing is STRATIFIED BY HTTP METHOD: within each
         method, both classes are trimmed to min(ALLOW, BLOCK). This forces
         P(BLOCK | method) = 0.5 exactly and yields 1:1 overall as a
         by-product. Trimming only; nothing is duplicated (D14).

  Result: HTTP method 56.37% -> 50.00% (+0.00).
  Cost: 38,743 train rows and 6,800 eval rows trimmed. Recorded in section 8.

4. CAUSAL EXCEPTIONS — ENVELOPE FEATURES ALLOWED TO CORRELATE
==============================================================================
Per E2 section B, features that constitute part of the attack are NOT
neutralized. Each is documented in the manifest under
causal_envelope_exceptions. Measured behaviour on the candidate dataset:

  FEATURE                          ALLOW   BLOCK   PURITY   COVERAGE
  ------------------------------  ------  ------  -------  ---------
  Origin header PRESENT               38      46    54.8%         84
  Origin CROSS-ORIGIN vs Host          0      46   100.0%         46
  Transfer-Encoding present            0       5   100.0%          5
  duplicate param name in query        0      13   100.0%         13

  This is the designed behaviour. Header PRESENCE is non-predictive (54.8%),
  because benign counterparts in the same shape carry same-origin Origin and
  Referer. Only the cross-origin RELATIONSHIP — which IS the CSRF attack —
  correlates with BLOCK. Same pattern for smuggling framing headers (benign
  counterparts carry a single correct Content-Length) and for HPP (benign
  counterparts use the same parameter names without duplication).

  All three causal reveals fall below E0's 1%-coverage threshold, which is why
  E0 reports zero deterministic reveals. Their tiny coverage is itself a
  symptom of the scarcity problem in section 7 — there are only 46 CSRF rows
  and 5 smuggling rows in the entire dataset.

5. SOURCE EXTRACTION AND QUALITY FILTERING
==============================================================================
The historical extractor scraped any markdown line containing one of a set of
characters, which captured prose, table rows, reference links and unresolved
fuzzer placeholders.

New extraction: fenced code blocks and .txt wordlists ONLY. The prose heuristic
is removed entirely. Directory and file traversal is sorted for determinism.
XXE, Request Smuggling and Insecure Deserialization take the whole fenced block
as one payload, because line-splitting destroys their semantics.

A missing category directory is now a FATAL ERROR, not a silent [SKIP] — the
failure mode that cost v3 two categories is disarmed.

8. E3 — GROUPED SPLIT
==============================================================================
Group identity:
  attack   sha256 of a canonical key that undoes percent-encoding (3 layers),
           unicode escapes, HTML entities, inline SQL comments (/**/),
           ${IFS}, whitespace runs and case. An obfuscated variant therefore
           canonicalizes to the same group as its base payload.
  benign   shape | path | parameter | value
  CSIC     method | path | sorted(param=normalized value), with digits
           collapsed to '#' and percent-escapes decoded.

  The CSIC key deliberately goes beyond "record identity". Record identity
  alone would let `cantidad=1` sit in train and `cantidad=2` in eval — an
  exact-match gate would pass while genuine near-duplicate leakage remained.
  Collapsing digits puts all variants of one request shape in one group.
  Effect: 41,900 CSIC records collapse to 8,519 groups.

Split assignment: deterministic hash bucket,
  sha256(salt || group_id) mod 10000 < 2000 -> eval
Order-independent and stable regardless of dataset size or iteration order.

  GROUP COUNTS               TRAIN     EVAL

9. TRANSFORM POOLS (D15)
==============================================================================
Obfuscation is no longer both training augmentation and adversarial evidence.

  TRAINING POOL — used to generate augmented rows, always within the base
  group's own split, so no group crosses over:
    url_encode, case_variation, sql_comment_inject, whitespace_tab

  HELD-OUT POOL — defined, documented, and used to generate NOTHING in this
  dataset. Reserved exclusively for a future adversarial suite:
    double_url_encode      percent-encode, then encode each % as %25
    unicode_escape         escape < > ' " as \uXXXX
    html_entity            named/numeric HTML entity encoding
    bash_ifs               spaces -> ${IFS}; backtick exec -> $()
    mixed_case_percent     randomise hex case in percent-escapes
    param_fragmentation    split a payload across repeated parameters

  Consequence to disclose: robustness against held-out transforms is
  UNMEASURED by design. The adversarial suite is not implemented (D15).

10. DETERMINISM AND REPRODUCIBILITY
==============================================================================
The historical generator was non-deterministic despite random.seed(42):
list(set(payloads)) iteration order varies with PYTHONHASHSEED, and
os.listdir()/os.walk() are unsorted.

Fixed:
  * all directory and file traversal sorted
  * no reliance on set iteration order for anything that feeds the RNG
  * per-sample RNG seeded from the sample's group id, not from a global stream,
    so rendering is independent of processing order
  * deterministic hash-bucket split instead of a shuffled list
  * output rows sorted by content hash
